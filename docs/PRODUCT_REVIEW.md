# 제품 검토 보고서

## 총평

이 그룹웨어는 범용 대기업 시스템을 축소한 형태보다 실제 소기업의 보고 방식에 더 가깝습니다. 모든 직원이 직접 보고서를 쓰지 않는 현장 조직, 여러 법인 또는 업체명을 함께 운영하는 조직, 정기 회의에서 보고서를 바로 보여 주는 조직에 특히 적합합니다.

## 잘 된 부분

- 기존 일일 업무 흐름을 유지해 재교육 부담이 작습니다.
- 작업자 선택이 별도 작업자 보고서를 생성하지 않고 작성자의 본문 작성을 돕습니다.
- 회사 분리와 그룹 전체 열람을 함께 지원합니다.
- 직급 순 정렬과 보고 관계를 분리해 회의 열람 순서가 안정적입니다.
- 대시보드, 공통 메뉴와 주요 페이지의 정보 구조가 일관됩니다.
- PHP/MySQL만으로 동작해 저비용 호스팅에 올리기 쉽습니다.

## 이번 개선에서 해결한 부분

- 고정된 포털명과 회사명을 관리자 설정으로 전환
- 상단 보조 문구는 관리자가 명시한 경우에만 사용하고, 빈 값에서는 등록 회사명을 노출하지 않음
- 회의 요일과 `전주 실적 + 금주 계획` 기준 설정
- 주간 화면과 엑셀에 같은 기간 및 실제 날짜 표시
- 연속 일자 등록에서 토·일 기본 제외, 요일별 선택 포함
- 공개 배포에서 실제 업체명, DB 비밀번호와 첨부자료 제외
- 첫 설치의 첫 계정을 관리자로 만들고 임의 관리자 승급 경로 차단
- 가입 허용을 관리자가 끌 수 있도록 보완
- 반복 로그인 실패를 사용자·접속 주소 기준으로 제한하고 계정 존재 여부 노출 제거
- 로그인 성공 시 세션 ID 교체와 CSRF 검증 적용
- 로그인·계정·조직·결재선·API 설정 변경 감사 로그 제공
- 이미지와 일반 첨부파일의 MIME 유형·확장자·용량 서버 검증

## 남은 한계와 권장 순서

1. 백업 자동화: 무료호스팅에서는 정기 DB 백업을 사용자가 직접 내려받아야 합니다.
2. 외부 CDN: Tailwind, 아이콘과 에디터를 CDN에서 불러오므로 외부망 장애 시 일부 UI가 영향을 받습니다.
3. 알림: 무료호스팅의 메일 제한을 고려해 사이트 내부 알림함을 먼저 강화하는 편이 적합합니다.
4. 감사 로그 보존 정책: 조직 규모와 개인정보 정책에 맞춰 보관 기간과 정리 절차를 정해야 합니다.
5. 계정 복구: 메일 발송 없이 안전하게 비밀번호를 초기화하는 관리자 절차를 더 명확히 만들 필요가 있습니다.

현재 규모에서 다음 우선순위는 백업 절차 단순화와 내부 알림함입니다. 실시간 채팅, 복잡한 프로젝트 간트차트나 급여 기능은 운영 복잡도를 크게 늘리므로 실제 필요가 확인된 뒤 별도 모듈로 추가하는 것이 좋습니다.
